\# Contributing Guidelines



Here Will be written the strategies that I want you to follow when making a contribution, please follow them:



\## 1. Branching Strategy

\- Do not commit directly to the `main` (or `master`) branch.

\- Create a new branch for your changes using these prefixes:

&#x20; - `feature/` for new additions (e.g., `feature/new-discount`)

&#x20; - `fix/` for bug corrections (e.g., `fix/invoice-error`)

&#x20; - `docs/` for documentation (e.g., `docs/readme-update`)





\## 2. Pull Request (PR) Guidelines

\- Open your PR targeting the `main` branch.

\- Provide a clear description of what you changed and why.

\- Ensure your Java code compiles without errors and includes Javadoc comments.

\- Your PR must be reviewed and approved by a collaborator before merging.
